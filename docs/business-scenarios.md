# 旅游规划业务场景

TravelAgent 的所有 lesson 都围绕同一个业务：把自然语言旅行需求转成可执行、可解释、可评估的旅行方案。

## 核心用户旅程

1. 用户提出模糊旅行需求。
2. Agent 抽取目的地、日期、人数、预算、偏好和约束。
3. Agent 主动追问缺失的关键信息。
4. Agent 调用地图、天气、POI、路线等工具。
5. Agent 生成候选行程。
6. Agent 检查预算、节奏、天气、交通和风险。
7. Agent 输出最终方案并支持用户反馈修改。

## 第一批业务场景

| 场景 | 典型需求 | 关键难点 |
| --- | --- | --- |
| 自由行规划 | “下个月去日本 5 天，预算 12000，想轻松一点。” | 目的地选择、预算、节奏控制 |
| 亲子游 | “暑假带孩子去云南 7 天，安全轻松。” | 安全、体力、亲子活动、天气 |
| 商务差旅 | “上海出差空出两天，想吃好逛好。” | 时间碎片、交通效率、餐饮推荐 |
| 低预算旅行 | “学生党成都 4 天，预算 2000。” | 成本控制、住宿和交通取舍 |
| 多人偏好协调 | “四个朋友去北京，有人想历史有人想美食。” | 偏好冲突、路线折中 |
| 临时变更 | “明天下雨，帮我把户外行程改掉。” | 天气风险、备选方案、重规划 |

## 业务对象

| 对象 | 说明 |
| --- | --- |
| TravelRequest | 本次旅行需求和约束 |
| TravelerProfile | 用户长期偏好和限制 |
| Destination | 城市、区域、签证、季节和预算水平 |
| POI | 景点、餐厅、商圈、交通节点 |
| Itinerary | 每日行程和时间安排 |
| BudgetEstimate | 住宿、餐饮、交通、门票等费用估算 |
| RiskReport | 天气、交通、签证、安全、过度赶路等风险 |
| EvaluationResult | 方案质量评分和问题定位 |

## 业务边界

- 本项目做旅行规划和推荐，不做真实下单。
- 酒店、航班、火车票只作为未来工具契约和推荐信息，不处理支付、库存锁定或退改签。
- 输出需要标明假设、信息来源和需用户确认的部分。
- 涉及签证、安全、医疗等高风险信息时，应提示用户核验官方来源。
