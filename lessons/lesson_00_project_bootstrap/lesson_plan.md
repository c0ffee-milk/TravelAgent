# Lesson 00 课案：项目启动与业务建模

## 课程目标

本课帮助学习者在写代码前建立 TravelAgent 的业务地图。重点是把“旅游规划 Agent”拆成可理解、可建模、可逐步实现的系统，而不是直接进入框架或 API 调用。

## 课程边界

本课包含：

- 旅游规划业务流程。
- Agent 与普通聊天机器人的差异。
- 核心业务对象识别。
- 一条旅行需求的结构化拆解。
- 后续课程路线解释。

本课不包含：

- Python 代码。
- DeepSeek API 调用。
- 高德地图或和风天气调用。
- Agent 框架实现。
- 自动评估 runner。

## 教学顺序

### 1. 项目开场：为什么选择旅游规划 Agent

建议时长：10 分钟

讲解要点：

- 旅游规划不是单轮问答，而是多约束、多步骤、多工具任务。
- 用户需求通常不完整，需要 Agent 主动澄清。
- 旅行方案需要外部事实支撑，例如地点、路线、天气、预算。
- 旅行规划天然适合逐步引入 Agent 技术。

核心结论：

> TravelAgent 的目标不是“会聊天”，而是“围绕旅行目标持续推进任务并交付可执行方案”。

### 2. 定义端到端用户旅程

建议时长：10 分钟

使用流程：

```text
用户提出模糊需求
  -> Agent 抽取关键信息
  -> Agent 追问缺失字段
  -> Agent 调用外部工具
  -> Agent 生成候选方案
  -> Agent 检查预算和风险
  -> Agent 输出最终行程
  -> 用户反馈后重规划
```

讲解时强调：

- 每一步都对应后续一个或多个 lesson。
- 不要把最终系统一次性写完。
- 每一课只解决一个清晰的业务痛点。

### 3. Agent 与普通聊天机器人的差异

建议时长：10 分钟

对比维度：

| 维度 | 普通聊天机器人 | 旅游规划 Agent |
| --- | --- | --- |
| 目标 | 回答当前问题 | 完成旅行规划任务 |
| 状态 | 通常弱状态 | 需要维护需求、工具结果和修改历史 |
| 工具 | 可无工具 | 需要地图、天气、POI、预算等工具 |
| 输出 | 自然语言为主 | 结构化方案 + 解释 + 风险 |
| 质量判断 | 回答是否像样 | 是否满足日期、预算、偏好和安全约束 |

教学重点：

- Agent 需要目标、状态、行动和反馈。
- 后续所有技术都围绕这四件事展开。

### 4. 建立核心业务对象

建议时长：15 分钟

引导学习者识别以下对象：

| 对象 | 关键字段示例 | 后续课程用途 |
| --- | --- | --- |
| `TravelRequest` | 目的地、日期、天数、人数、预算、偏好 | 需求澄清、结构化输出 |
| `TravelerProfile` | 饮食偏好、体力、酒店偏好、禁忌 | 用户记忆 |
| `Destination` | 城市、季节、交通、预算水平 | RAG 和目的地研究 |
| `POI` | 名称、位置、类型、开放时间、适合人群 | 地图工具 |
| `Itinerary` | day、时间段、地点、交通、费用 | 最终输出 |
| `BudgetEstimate` | 住宿、交通、餐饮、门票 | 预算检查 |
| `RiskReport` | 天气、交通、安全、体力、签证 | 风险审稿 |
| `EvaluationResult` | 约束满足、事实可靠、行程可执行 | 自动评估 |

讲解方式：

- 不要求现在写 schema。
- 先让学习者理解每个对象解决什么业务问题。
- 后续 lesson 再逐步把这些对象转成代码。

### 5. 课堂案例拆解

建议时长：20 分钟

案例：

```text
暑假想带 8 岁孩子和父母去云南玩 7 天，预算 18000，希望安全轻松，不要太累。
```

引导问题：

1. 用户是谁？
2. 本次旅行的主要目标是什么？
3. 已知约束有哪些？
4. 缺失信息有哪些？
5. 哪些信息必须追问？
6. 哪些信息可以先做假设？
7. 需要哪些外部工具？
8. 最终方案应该包含哪些部分？

参考拆解：

```text
用户画像：
- 家庭旅行，包含 8 岁孩子和父母。
- 对安全、轻松、体力消耗敏感。

已知需求：
- 目的地：云南。
- 时间：暑假。
- 天数：7 天。
- 预算：18000 元。
- 偏好：安全、轻松、不太累。

缺失信息：
- 出发城市。
- 具体日期。
- 总人数是否为 4 人。
- 交通方式偏好。
- 酒店档位。
- 饮食禁忌。

需要追问：
- 从哪个城市出发？
- 暑假中具体哪几天？
- 父母和孩子的体力情况如何？
- 更偏好自然风景、古城文化，还是亲子活动？

需要工具：
- 地图/路线工具。
- 天气工具。
- POI 搜索工具。
- 预算估算工具。

最终方案结构：
- 需求摘要。
- 每日行程。
- 交通安排。
- 预算拆分。
- 亲子和老人友好说明。
- 天气和安全风险。
- 需要用户确认的问题。
```

### 6. 映射到课程路线

建议时长：10 分钟

将本课拆出的业务问题映射到后续 lesson：

| 业务问题 | 后续 lesson |
| --- | --- |
| 信息不完整 | Lesson 01：需求澄清 |
| 需要自然语言理解 | Lesson 02：LLM Provider |
| 需要地点和路线 | Lesson 03：地图工具 |
| 需要天气风险 | Lesson 04：天气工具 |
| 需要动态查询 | Lesson 05：ReAct Agent |
| 需要复杂任务拆解 | Lesson 06：规划型 Agent |
| 需要目的地资料 | Lesson 07：RAG |
| 需要记住用户偏好 | Lesson 08：用户记忆 |
| 需要多角色审核 | Lesson 09：多智能体 |
| 需要判断好坏 | Lesson 10：评估 |
| 需要对外使用 | Lesson 11：服务化 |

### 7. 课堂小结

建议时长：5 分钟

强调三点：

- 先建模业务，再选择技术。
- Agent 的能力来自目标、状态、工具、反馈的组合。
- TravelAgent 后续每一课都应该解决一个真实业务痛点。

## 学习者课后产物

学习者完成本课后，应产出一份自己的业务拆解笔记，至少包含：

- 一个旅行需求样例。
- 已知字段。
- 缺失字段。
- 追问问题。
- 需要的工具。
- 最终方案结构。
- 对应后续 lesson 的技术需求。

## 教师检查点

检查学习者是否理解：

- 旅游规划 Agent 的目标不是生成漂亮文案，而是满足约束并交付可执行方案。
- 缺失信息不应随意编造，应追问或显式假设。
- 外部工具用于补足模型不知道或容易过期的事实。
- 评估不是最后才考虑，而是从业务对象和约束中自然产生。
