# Lesson 00：项目启动与业务建模

本课是 TravelAgent 教学项目的起点。目标不是写代码，而是先把“旅游规划 Agent”这个真实业务拆清楚：用户是谁、要解决什么问题、Agent 需要理解哪些对象、后续每一课为什么要引入新的 Agent 技术。

## 业务背景

TravelAgent 面向的核心任务是：

> 把用户模糊的自然语言旅行需求，转成可执行、可解释、可评估的旅行方案。

典型输入：

```text
下个月想和女朋友去日本玩 5 天，预算 12000，希望轻松一点，不想每天赶路。
```

最终系统需要逐步具备：

- 识别目的地、日期、天数、人数、预算、偏好和限制。
- 主动追问缺失信息。
- 查询地图、天气、POI、路线等外部信息。
- 生成每日行程、预算估算和风险提示。
- 根据用户反馈修改方案。
- 记录用户偏好，并在下次规划中复用。

## 本课核心概念

### 1. Agent 不是普通聊天机器人

普通聊天机器人主要回答问题；旅游规划 Agent 需要围绕目标持续工作：

- 理解用户目标。
- 维护任务状态。
- 拆解复杂任务。
- 调用外部工具。
- 检查约束和风险。
- 交付可执行结果。

### 2. 业务对象先于技术框架

在写 Agent 之前，先明确业务对象。TravelAgent 的第一批核心对象包括：

| 对象 | 说明 |
| --- | --- |
| `TravelRequest` | 本次旅行需求和约束 |
| `TravelerProfile` | 用户长期偏好和限制 |
| `Destination` | 目的地及其季节、交通、预算特征 |
| `POI` | 景点、餐厅、商圈、交通节点 |
| `Itinerary` | 每日行程安排 |
| `BudgetEstimate` | 交通、住宿、餐饮、门票等费用估算 |
| `RiskReport` | 天气、交通、签证、安全、体力等风险 |
| `EvaluationResult` | 对方案质量的评分和问题定位 |

### 3. 每个 lesson 都服务同一条业务主线

后续课程不会做互不相关的 Agent demo，而是在同一个旅游规划业务上逐步升级：

1. 业务建模。
2. 需求澄清。
3. DeepSeek LLM Provider。
4. 高德地图工具。
5. 和风天气工具。
6. ReAct Agent。
7. 规划型 Agent。
8. RAG 知识库。
9. 用户记忆。
10. 多智能体协作。
11. 评估与服务化。

## 本课任务

请围绕下面这条需求完成业务建模：

```text
暑假想带 8 岁孩子和父母去云南玩 7 天，预算 18000，希望安全轻松，不要太累。
```

你需要产出：

1. 用户是谁。
2. 本次旅行目标是什么。
3. 已知约束有哪些。
4. 缺失信息有哪些。
5. Agent 应该追问哪些问题。
6. 需要哪些外部工具。
7. 最终旅行方案至少应包含哪些部分。
